可以。这里真正值得展开的是：**我们不是简单把错误的单一 `model_sequence` 修正成另一个单一序列，而是在重新定义 EGR 的监督对象。** 这会让整个项目从“模仿数据集中的步骤顺序”升级成“学习在当前数学状态下，哪些 theorem actions 是可执行且有价值的”。

### 1. 先区分三个概念

原来的设定近似是：

\[ S_t \rightarrow M_t^{gold} \rightarrow S_{t+1} \]

即每个状态只有一个 gold next model。问题是，这个 \(M_t^{gold}\) 来自自然语言 `process` 的二次抽取，而自然语言本身不保证严格按照计算执行顺序叙述。因此，“预测错 gold model”不一定意味着数学推理错。

我建议改成：

\[ S_t \rightarrow \mathcal A^{+}(S_t) \rightarrow a_t \rightarrow S_{t+1} \]

其中：

\[ \mathcal A^{+}(S_t)= \{a_1,a_2,\ldots,a_k\} \]

表示**在当前状态下已经被系统验证为合理的下一动作集合**。Selector 的任务变成：

> Given the current reasoning state, select a valid and promising theorem action.

这比“复现人工解答中的下一个模型编号”更符合 EGR 的研究目标。

------

### 2. 这个集合不是直接从 Conic10K 读出来的

这是最重要的一点。

假设一道题的人类 `process` 暗示：

\[ M_{13}\rightarrow M_{27}\rightarrow M_{41}\rightarrow Answer \]

我们不能因此认为：

\[ A^+(S_0)=\{M_{13}\} \]

因为也许存在另一条完全正确的路径：

\[ M_{27}\rightarrow M_{13}\rightarrow M_{41}\rightarrow Answer \]

甚至：

\[ M_{52}\rightarrow M_{41}\rightarrow Answer \]

所以 Conic10K 提供的是一个**reference solution clue**，不是完整 action supervision。

真正的 \(A^+(S)\) 应该由：

**dataset weak supervision + theorem applicability + symbolic execution + bounded search + answer verification**

共同构建。

这实际上可以成为你论文里一个相当有特色的方法点。

------

### 3. 具体怎样离线构建 \(A^+(S)\)

例如当前状态为 \(S_t\)。

第一层先做 **Applicability Filtering**。80 个模型并不是全部拿去深搜，而是根据 theorem 的 `precondition`：

\[ C(S_t)=\{M_i\mid Precondition(M_i,S_t)=True\} \]

假设 80 个只剩：

\[ C(S_t)=\{M_5,M_{13},M_{27},M_{38},M_{41}\} \]

然后进行参数绑定。例如 \(M_{27}\) 不是抽象地“应用 Model 27”，而是：

\[ a=(M_{27},\theta) \]

这里 \(\theta\) 可能指定：

- 哪条直线；
- 哪个圆锥曲线；
- 哪两个点；
- 哪个未知参数；
- 哪个方程组。

因此真正执行的是 theorem **instance**。

接着执行：

\[ S'_i=T(S_t,a_i) \]

如果：

- 执行失败；
- 得不到任何新事实；
- 产生矛盾；
- 前置条件其实不满足；

就直接排除。

最后从每个 \(S'_i\) 继续有限深度搜索：

\[ S'_i \rightarrow \cdots \rightarrow S_{goal} \]

如果最终得到的答案能够通过 symbolic verifier：

\[ Verify(S_{goal},y^{gold})=1 \]

那么当前 \(a_i\) 就获得一个非常强的证据：

> 从这个动作出发，至少存在一条系统已经找到并符号验证成功的后续路径。

因此进入 `verified_positive`。

------

### 4. 但“能到答案”还太宽松

这是前面 \(A_\delta^+(S)\) 的意义。

假设三个动作都能到正确答案：

\[ M_{13}: 4\ steps \]\[ M_{27}: 5\ steps \]\[ M_{52}: 17\ steps \]

第三个虽然理论上也能求出来，却可能是非常绕、甚至包含大量无关操作。

因此定义最优剩余代价：

\[ d^*(S)=\min_{\pi:S\rightarrow Goal}Cost(\pi) \]

对于动作 \(a\)：

\[ Q^*(S,a) = Cost(a)+d^*(T(S,a)) \]

只接受：

\[ Q^*(S,a)\le d^*(S)+\delta \]

于是：

\[ A_\delta^+(S) = \{a:Q^*(S,a)\le d^*(S)+\delta\} \]

例如 \(\delta=2\)，那么 4 步、5 步路径都可以作为合理监督，而 17 步路径不进入 positive set。

这实际上已经开始接近一个**数学推理 policy learning / planning** 问题，而不是普通 80 类分类。

------

### 5. 原始 `models` 序列仍然非常有价值

我们并不是把现有数据扔掉。

它可以从 **gold sequence** 降级成：

\[ \text{Reference Action Set / Search Prior} \]

比如原始 `models` 是：

\[ [13,27,41,52] \]

即使顺序不可靠，它仍然告诉我们：

> 这道题的人类解答很可能涉及这些 theorem schemas。

于是搜索时可以优先扩展这些动作：

\[ P_{prior}(M_i\mid process) \]

而不是对 80 个 theorem 完全均匀搜索。

因此数据集的信息仍被充分利用，只是不再做一个过强、实际上并不成立的假设：

> `models[0], models[1], ...` 就是唯一正确执行顺序。

------

### 6. Partial-order graph 也不必一开始就“人工标出来”

这一点也很重要。

假设我们已经找到两条验证成功路径：

\[ A\rightarrow B\rightarrow C\rightarrow D \]

以及：

\[ B\rightarrow A\rightarrow C\rightarrow D \]

并且执行后：

\[ T_B(T_A(S)) \equiv T_A(T_B(S)) \]

那么系统可以推断：

\[ A\parallel B \]

但：

\[ A,B \prec C \prec D \]

所以得到的不是：

\[ A\rightarrow B\rightarrow C\rightarrow D \]

这样一个强制线性序列，而是：

\[ \{A,B\}\rightarrow C\rightarrow D \]

这就是 partial-order solution structure。

它特别适合你现在的数据问题，因为**中文解答里两个独立步骤先说谁后说谁，本来就未必具有数学意义。**

------

### 7. 这会反过来改变 Selector

原来的 selector：

\[ P(M_i\mid S) \]

然后拿唯一 gold label 做 Cross Entropy：

\[ -\log P(M_{gold}\mid S) \]

新的训练方式则是：

\[ -\log \sum_{M_i\in A_\delta^+(S)} P(M_i\mid S) \]

举个最直观的例子：

真实有效集合：

\[ A^+(S)=\{13,27,41\} \]

模型预测：

\[ P(13)=0.15,\quad P(27)=0.55,\quad P(41)=0.20 \]

那么有效动作总概率：

\[ 0.15+0.55+0.20=0.90 \]

即使原始自然语言恰好先写 Model 13，而 selector 选择了 Model 27，也**不应该被判错**。

这会直接解决你目前 28 维 state 大量 label collision 的一部分问题。

------

### 8. 我建议再进一步：不要只有 Positive / Negative

最终训练资产最好保存四层信息：

| 标签              | 含义                     | 训练处理           |
| ----------------- | ------------------------ | ------------------ |
| Reference         | 原自然语言解答支持       | prior / preference |
| Verified Positive | 已验证存在高质量成功续接 | 正监督             |
| Verified Negative | 不可执行/矛盾/明确失败   | 负监督             |
| Unknown           | 搜索预算内无法证明       | mask               |

尤其最后一个非常关键。

假设 \(M_{36}\) 搜索 8 层没有找到答案，不能写：

\[ M_{36}=negative \]

只能写：

\[ M_{36}=unknown \]

因为 bounded search 没找到，不等于数学上不存在。

这样论文里的 claim 会严谨很多。

------

### 9. 这也给你的 EGR 一个更清楚的研究定位

我现在反而认为，这个数据问题如果处理好，不只是“修数据 bug”，而可能帮助我们把 EGR 的核心思想讲得更漂亮：

> **EGR does not imitate a single textual rationale. It learns to navigate a verified executable reasoning space.**

整个框架可以形成：

\[ \boxed{ \text{Problem} \rightarrow S_0 \rightarrow \underbrace{A(S_t)}_{\text{applicable actions}} \rightarrow \underbrace{\pi(a|S_t)}_{\text{learned selection}} \rightarrow \underbrace{T(S_t,a)}_{\text{symbolic execution}} \rightarrow S_{t+1} \rightarrow Goal } \]

而 Conic10K 的自然语言 rationale 只是为这个 reasoning space 提供 **weak structural supervision / search priors**，symbolic execution 才负责确定动作是否真正成立。

这比“80 类 theorem model sequence classification”要强很多，也更符合你想突出**复杂问题表征 + 多步推理 + 模型选择 + 模型应用 + 符号计算**的研究定位。

------

至于上一轮最后那个问题，我现在建议我们把标准定得稍微比“任何符号正确路径都算成功”更精确：

**Hard correctness：** 最终答案正确 + 每一步可执行 + 每个中间状态数学一致。

**Reasoning quality：** 路径长度、冗余动作、搜索成本、回溯次数、query relevance。

**Human/reference alignment：** 与原始 `process` / theorem set 的一致程度，只作为辅助评价。

这样“数学正确性”和“解法质量”不会混为一谈。

接下来真正需要与你对齐的第三个问题是：**你希望 EGR 的 Selector 最终只预测 `Model ID`，然后由独立的 Grounder 自动完成参数绑定；还是 Selector 直接预测完整的 `(Model ID, parameter binding)`？** 我目前明显更倾向前者——`Selector → Grounder → Applicator` 三层分离，因为这会让 80 个 theorem models 的语义更稳定，也更容易做 KBS 论文中的可解释性与消融实验。
