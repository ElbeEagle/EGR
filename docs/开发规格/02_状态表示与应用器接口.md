# 状态表示与应用器接口 v0.2

日期：2026-09-23。状态：D1–D4 已确认；其余为开发草案，不是现有 API 文档。

依据：[模型 ID](../../model/conic_model_ids.json)、[模型说明](../../model/conic_model_descriptions.md)、[对象词表](../../model/object.json)、[操作符词表](../../model/operators.json)及[五个真实案例](05_真实题目转换案例.md)。

## 1. 固定设计边界

1. 保留双层状态和 80 个高层模型 ID；具体应用方式可以扩展。
2. Selector 预测模型 ID；应用器负责应用方式与对象绑定候选。多个绑定不得只取第一个匹配对象。
3. 模型执行其声明的数学关系及相关代数计算；公共操作不自行遍历定理或规划完整解题路径。
4. 训练轨迹与自主求解使用同一个初态构造入口和同一个应用器。
5. 初始化仅解析给定事实、建立对象引用和进行有依据的等价规范化；模型参数提取等推理进入可记录动作。
6. 测试时输入为 facts、query 及由原题明确确定的 query_mode；`process`、`models`、参考答案只进入离线分析／监督／评价。
7. 本轮不含熵控制；停止依据是查询目标已经确定且满足其答案要求。预算耗尽、无进展是失败／未完成状态。

## 2. 表达语言与公共操作分层

`operators.json` 的词条需要按语义分类，例如：

| 类别 | 现有词条例子 | 内部责任 |
| --- | --- | --- |
| 对象构造／引用 | `LineOf`、`TriangleOf`、`Focus`、`OneOf` | 建立带类型的对象项及角色，保留集合与成员语义 |
| 属性访问 | `Coordinate`、`Expression`、`Eccentricity` | 指向对象的属性或查询目标 |
| 数学关系 | `PointOnCurve`、`IsPerpendicular`、`Intersection` | 保存可实例化的结构化事实 |
| 查询／约束表达 | `Range`、`Max`、`Eq` | 按上下文解析为查询、表达式或条件 |
| 数学函数 | `sqrt`、`Abs`、`Sin` | 映射到受控的精确表达式操作 |

分类不强制互斥；以表达式上下文判定。保留原始词形与解析来源；`axis/Axis`、`ImageinaryAxis` 等别名或拼写问题需建立显式映射，不能静默改写原始数据。未知词条返回解析诊断。

## 3. SymbolicState：保留概念，完善结构

以下为建议语义字段，具体类名和存储形式尚未冻结。

| 概念 | 建议内容 | 对应当前结构 |
| --- | --- | --- |
| 对象表 | 稳定 ID、类型、角色关联；允许由 `LineOf(A,B)` 等对象项构造规范引用 | `entities` |
| 原题符号表 | 符号 ID、作用域、数域；原题 `m` 与内部辅助符号分开 | `entities/parameters` 的一部分 |
| 对象属性 | `(owner_id, property)` 指向数值或精确表达式，如 `G.a_sq` | `parameters` |
| 方程事实 | fact ID、表达式、自由符号、关联对象、定义域／附带条件 | `equations` |
| 几何关系 | 类型化谓词和参数列表；如 `PointOnCurve(A,G)` | `geometric_relations` |
| 坐标 | 点 ID 到坐标表达式的映射；坐标轴／坐标系明确 | `coordinates` |
| 约束 | 等式、不等式、非零／实数条件及有效分支 | `constraints` |
| 查询 | 目标对象／表达式、答案类型与要求 | 新增，不能只保存粗粒度 query_type |
| 来源 | 给定事实来源或 model、binding、输入 fact IDs、操作记录 | 新增 |
| 控制历史 | 动作尝试、结果、状态版本、失败和预算 | 从 `applied_models` 扩展，独立于数学事实 |

### 3.1 必须处理的语义

- `G.a_sq` 是对象属性示意，不是字符串拼接 API。两条曲线的参数不能共用全局 `a,b,c`；局部二次方程系数使用该方程作用域的 `A,B,C`。
- 原题中的字母 `a` 可能只是某方程的待求系数，不能自动等同于椭圆半长轴。
- 保留原始表达和规范表达。运行时用受控解析产生精确符号对象，持久化使用版本化表达树或受限可解析格式；具体序列化方案待小批实现验证。
- 符号关系也是信息：`G.b_sq = m²` 无需等待数值化。得到 `m=5` 后建立可追溯的等价求值结果，不丢弃原关系。
- 等价方程／重复事实共享规范索引，来源可以追加。无法证明等价时不擅自合并。
- `Focus(G)` 对双曲线／椭圆通常是焦点集合，对抛物线是单个焦点；集合相等不能直接当作两个点逐个同名。
- 消元方程必须记录保留变量、消去变量、来源方程、交点对象及根的对应关系。若只使用对称式，不人为固定根到 A/B 的顺序。
- 同时保存的事实必须共同成立。互斥分支中的赋值不得写入同一状态。

### 3.2 AbstractState

继续由 `phi(symbolic_state, query, control_summary)` 生成；至少区分曲线对象与方向、已知属性身份、关键关系和目标所缺信息。控制摘要与数学内容分开编码。28 维版本可作为迁移基线，但维度与主网络不在本批冻结。

## 4. 模型应用规格及接口草案

每个模型包含多个显式应用方式。规格字段统一为：

```text
model_id / name / specification_version
mode / mathematical_scope
binding_roles: 对象、方程、点、目标属性的类型要求
required_facts / preconditions
operations: 有序公共操作及参数
outputs / postconditions
domain_conditions / branch_behavior
no_op_condition / failure_codes
source_case_ids / verification_status / unresolved_questions
```

建议调用关系（尚不存在的接口，不是可直接调用代码）：

```text
enumerate_bindings(state, query, model_id) -> BoundAction candidates
check(state, action) -> satisfied | rejected | unknown + evidence
propose(state, action) -> CandidateDelta(s) + operation_trace
validate_and_commit(state, proposal) -> TransitionResult
```

`BoundAction` 保存模型 ID、应用方式、绑定、规格版本及读取的 fact IDs。候选枚举使用稳定顺序；枚举不全或被预算截断要标记，不能宣称不存在其他绑定。

`CandidateDelta` 保存新增对象、事实、约束和属性关系；先在隔离副本／候选变化上计算，完成受限归约及检查后一次性提交。新辅助符号使用动作作用域生成，避免污染原题符号。

`TransitionResult` 至少包含状态、动作、输入事实、状态版本、delta、操作轨迹、检查结果和诊断。推荐结果状态：

| 状态 | 含义及行为 |
| --- | --- |
| `applied` | 产生非空语义变化，局部后置条件通过，提交 |
| `inapplicable` | 绑定不合法或必要输入缺失；给出原因，不提交 |
| `undetermined` | 必须成立的条件暂时不能判定，不当作成立 |
| `no_op` | 未增加语义信息；不得仅因历史列表增长算成功 |
| `conflict` | 推导候选与已有事实发生已证实矛盾；原状态不变 |
| `failed` | 解析、计算错误、超时或不支持；不能等同于数学无解 |
| `branched` | 提出互斥条件下的多个后继，交由控制器处理 |

检查只承诺所声明的局部数学条件，不宣称每步完成一般逻辑一致性证明。冲突需记录证据；检查器未知不能伪装为通过。

## 5. 公共操作首批候选

| 操作职责 | 输入 → 输出 | 本批依据 |
| --- | --- | --- |
| 标准形式识别 | 指定曲线方程 → 中心、方向和系数匹配证据 | ID 2、9 |
| 直线系数处理 | 指定直线方程 → 系数、斜率或不可定义条件 | ID 2 |
| 关系实例化 | 已知关系＋绑定对象 → 该关系的具体代数约束 | ID 9 共焦点；不是任意定理搜索 |
| 代入与消元 | 指定方程组、消元变量 → 新方程及有效条件 | ID 56 |
| 多项式系数提取 | 方程、主变量 → 作用域内的系数及非退化条件 | ID 56 |
| 方程求解与筛选 | 约束组、目标符号、定义域 → 解集、条件、完备性状态 | ID 2、9、56 |
| 精确化简与回代 | 表达式、可用等式、非零条件 → 等价结果与证据 | 三题 |
| 状态差异检查 | 原状态与候选事实 → 新增／等价／冲突／未知 | 三题 |

每个操作返回条件与失败信息，不能返回一个未经说明的首解。操作记录必须说明读了哪些事实；模型内求解只读取声明的输入事实；提交前的受限归约可以更新由本次赋值影响的已有表达式，但不对全库自动饱和推理。

## 6. 多解、重复、终止与答案抽取

- 解集是查询结果时，保留全部解；交点的一对根作为共同对象信息保存，不自动创建互斥分支。
- 为继续推理必须选择某个互斥假设时，分别建立后继状态。约束不能筛成唯一解时，不可任意选根。
- 查询模式至少预留 `unique_value / all_solutions / any_witness`。ID 51 属于 `any_witness`，其余四题按确定目标处理。`Expression(G)` 不能独自决定模式；从原题“写出一个”等显式要求确定，保存来源片段。若接口只提供形式化 query 且没有模式信息，返回待确定，不擅自选择实例。
- 重复判断基于语义 delta 和绑定。相同模型可作用于不同对象，也可在新事实出现后再次调用。失败缓存必须依赖状态版本，不能永久封禁 ID。
- `AnswerReady` 检查目标结果、定义域、未解决条件和查询要求。抽取器只读取及规范化已有结果；引入新数学关系或求解未解约束属于模型执行。
- 离线答案比较器可接触参考答案；运行时抽取、绑定、分支和停止均不可读取参考答案。

### 8.1 受限归约：作为动作提交的一部分

新赋值产生后，只对依赖该赋值的已有表达式执行精确代入、化简和等价结果更新，保留原表达及来源。记录 `trigger_action / substitution / affected_fact_ids / resulting_facts`；无新增语义时不生成新推理步。

例如 ID 56 的 RM55 得到 u=−1/2 后，同一提交事务把已有 `x=u*y+1` 归约为 `2x+y−2=0`。答案抽取器只读取结果。

禁止归约阶段引入新定理、求解其他未知量或生成未声明的对象／分支。遇到无法判断的条件，不把条件结果升级为无条件事实。对等价变化去重，使用依赖队列和预算限制循环；预算耗尽保留明确诊断，不能标记完整归约成功。全程不新增 selector 标签。
