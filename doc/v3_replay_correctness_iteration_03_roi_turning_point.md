# V3 正确性迭代 03：收益拐点

## 结论

本阶段已经到达明显的性价比拐点。继续扩展表达式规范化可以提升 `APPLIED` 和完整回放率，但几乎不再提升“序列导致正确答案”的严格轨迹数。下一阶段应从通用 applicator 扩展转向：几何条件约束化、标签缺步修复和最小求解链搜索。

## 本轮改动

- GoalChecker 新增抛物线焦点到准线距离、双曲线焦点到渐近线距离、椭圆焦点三角形周长、椭圆两焦距和读取。
- 修复双曲线定义不能用于焦距和的问题，并增加负向回归测试。
- 新增初始目标检查；严格轨迹要求初始答案不正确、最终答案正确，排除无因果进展样本。
- 完善符号有理系数规范化：处理 `-1*(1/m^2)`、符号式除以有理数、嵌套乘法数值因子合并。
- 增加 `ResolvedParameterOf`，保留原符号表达式，同时允许定理写入已求得参数值。
- 解析轴长给定事实，并在恰有两个确定参数时由模型 11/12 求第三个参数。

## 为什么应调整方向

新增完整序列主要落入 `VALUE_UNRESOLVED` 或 `GOAL_NOT_REACHED`。典型题已经成功应用标准式、参数关系、渐近线等定理，但诸如垂直、共线、中点、切线、面积比例、焦点关联等几何条件尚未形成 scoped equations。因此再增强表达式化简只能让符号链走得更远，不能决定未知参数。

另外，模型 2/3/5 的大量首失败包含标签缺步、反向使用或题目根本没有相应输入。继续放宽 theorem precondition 会制造错误应用。

## 建议的新方向

1. 建立 `condition -> EquationConstraint` 层，优先覆盖高频且可精确执行的垂直、共线、中点、点在线/曲线上、焦点与顶点坐标关系。
2. 对完整但未解出的 76 条 `VALUE_UNRESOLVED` 做模板聚类，每实现一个约束 executor 就跑严格答案增量。
3. 对模型 2/3/5 首失败做标签操作：缺步插入、反向定理标记、确定错位删除；不再靠放宽 applicator 修标签。
4. 增加最小补全链搜索：只允许插入唯一适用且能让目标从 unresolved 变为 correct 的定理，产出独立的 corrected sequence 字段。
5. selector 训练先使用当前 198 条严格轨迹，并按唯一适用步骤与多候选步骤分层。

验证：68 条 unittest 全部通过，源码、脚本和测试通过 `compileall`。
